# Відновлені дані HR-VPP для T34UGV і території на схід від нього: що лежить у папці

Ця папка містить відновлені параметри фенології Copernicus HR-VPP (сезон 1) там, де офіційних даних немає:
тайл Sentinel-2 **T34UGV** (Івано-Франківщина, Калуш, Стрий) і розширення **T34UGVE** на схід від нього
(приблизно 25,1–26,1° сх. д., 48,6–50,2° пн. ш., зокрема Тернопільщина). Роки 2017–2024. За 2025 рік офіційних
даних HR-VPP ще немає, тож відновлення не можна відкалібрувати й перевірити.

Код, методика й інструкція для повторення: https://github.com/yevheniikhan/hrvpp-tile-recovery

## 1. Що брати для роботи

**Папка `Copernicus_Phenology/`**: остаточні файли у структурі MONIFUN.

```
Copernicus_Phenology/<параметр>/<рік>/VPP_<рік>_S2_<тайл>-010m_RECON_s1_<параметр>.tif
```

| що | значення |
|---|---|
| параметри | AMPL, LENGTH, RSLOPE, TPROD (сезон 1) |
| тайли | T34UGV і T34UGVE |
| роки | 2017–2024 |
| файлів | 64 (2 тайли × 4 параметри × 8 років) |
| система координат | WGS 84 / UTM 34N (EPSG:32634), 10 м |
| кодування | як в офіційних файлах: тип даних, масштаб, nodata, опис каналу, одиниці, `PhysRange` |

R-скрипти MONIFUN (`_run_extract_xbyx_*.R`) читають ці файли без змін, якщо покласти їх поруч з офіційними.
У назві кожного файлу є `_RECON_`, а в метаданих теги `SOURCE` і `CALIBRATION`. Це не офіційні продукти CLMS:
у таблиці ділянок НЛІ варто мати позначку для ділянок у T34UGV і T34UGVE, а в публікаціях вказувати, що дані
відновлені.

## 2. Наскільки їм можна довіряти

Коротко (повністю в `ПЕРЕВІРКА_пояснення.docx` і `docs/VALIDATION.md`). Відносна похибка після корекції,
перевірена на смугах, яких модель не бачила під час навчання:

| | AMPL | LENGTH | RSLOPE | TPROD |
|---|---|---|---|---|
| T34UGV, 2017–2024 | 20–26 % | 13–19 % | 39–51 % | 14–18 % |
| T34UGVE, 2018–2024 | 20–29 % | 16–21 % | 33–49 % | 16–21 % |

1. Найнадійніші TPROD і LENGTH, найслабший RSLOPE.
2. Найслабший рік 2020: найменше безхмарних знімків.
3. Розширення стикується з T34UGV у смузі перекриття 10 км майже без шва (r 0,96–0,99). Сезон у розширенні
   на 5–8 днів довший, ніж у T34UGV.
4. Дві незалежні реалізації (Google Earth Engine і окремий розрахунок на GPU зі знімками Microsoft Planetary
   Computer) дають узгоджені результати (r 0,81–0,99).
5. T34UGVE за 2017 рік відкалібровано на смугах T34UGV, за 2018–2024 роки на перекритті з офіційними T34UGA і
   T35ULP.

## 3. Решта папок

| папка або файл | що там | потрібно для роботи? |
|---|---|---|
| `Copernicus_Phenology/` | остаточні файли (розділ 1) | так |
| `ПЕРЕВІРКА_пояснення.docx` (і `.md`) | пояснення перевірки простою мовою | так, для звіту |
| `ПРОЧИТАЙ_СПОЧАТКУ.docx` (і `.md`) | цей опис | |
| `official/` | офіційні сусідні тайли HR-VPP 2017–2024 (T34UFV, T34UGA, T34UGU, T35ULP), за якими калібрували й перевіряли | ні, для перевірки |
| `Copernicus_Phenology_gpu/` | T34UGVE за 2021 і 2024 роки з другої, незалежної реалізації (GPU) | ні, для порівняння |
| `Copernicus_Phenology_v1_linear/` | перша версія T34UGV 2017–2023 з простою лінійною поправкою | ні, застаріла |
| `raw_ee/`, `raw_gpu/` | «сирі» розрахунки до корекції (частина років) | ні, для перевірки |
| `reports/` | таблиці перевірки (`11_*` T34UGV, `12_*` GPU, `13_*` розширення 2018–2024) | ні, для перевірки |
| `docs/` | методика, перевірка, інструкція з повторення, проблема скрипта завантаження MONIFUN | для фахівців |
| `src/`, `scripts/`, `gee/`, `notebooks/`, `tests/` | копія коду з GitHub | для повторення |

Сирі розрахунки розширення за 2018–2024 роки (до корекції) лежать в окремій спільній папці
`HRVPP_T34UGVE_export` у вигляді частин, які склеює `scripts/mosaic_shards.py`.

## 4. Як повторити або розширити

Покрокова інструкція: `docs/REPRODUCE.md` (англійською). Для іншої території достатньо задати прямокутник на
сітці 10 м і назвати офіційні тайли, з якими вона перекривається. Потрібні лише відкриті дані (Sentinel-2,
офіційні тайли HR-VPP з WEkEO) і власні облікові записи Earth Engine та WEkEO. Жодних паролів чи ідентифікаторів
проєктів у коді немає.

Стан на 12.11.2026.
